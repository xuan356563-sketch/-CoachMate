# AI 速报 Eval 框架

**目标**: 为「AI 速报-每日推送」skill 提供可重复的评分机制,确保 prompt 改动有客观依据。

**适用 skill**:
- `AI 速报-每日推送` cron (id: `3e029fad-049e-4d89-910c-cc78f60dc2d7`)
- 后续可扩展到 `xhs-sports-copywriter` / `daily-training-reminder` / `taskflow:content-pipeline`

---

## 📊 评分维度 (Rubric)

总分 10 分,分 5 个维度:

### 1. 结构合规 (2 分)
- 有 `# 🔥 AI 速报 | X月X日(周X)` 标题 → **+0.5**
- 包含 `## 📰 1️⃣` 到 `## 📰 8️⃣` 至少 5 条 → **+0.5**
- 包含 `## 🧠 独立思考` 段 → **+0.5**
- `━━━━━━━━━━━━━━━━━━` 分隔符正确 → **+0.5**

### 2. 禁词检测 (2 分)
- 出现「家人们/绝绝子/重磅/炸裂/绝美/yyds/绝绝子」→ **每个 -0.5**(扣到 0 止)
- 出现「纯八卦/人事变动」类内容 → **-1.0**

### 3. 信息来源 (2 分)
- 每条新闻标注「来源:[具体媒体名]」→ **每条 +0.25**(8 条满分 2 分)
- 媒体名为「网络/综合/未知」等模糊来源 → **每条 -0.5**

### 4. 领域覆盖 (2 分)
必须覆盖 6 个领域(每条新闻只算 1 个主领域):
- 重要产品发布(OpenAI/Google/Anthropic/国内)
- 融资事件/行业并购
- 技术突破/重要论文
- 行业标准/AI 安全
- 视频/影视/多媒体 AI 工具 ⭐
- 小红书平台动态 ⭐

- 覆盖 ≥5 个领域 → **+2.0**
- 覆盖 4 个领域 → **+1.0**
- 覆盖 3 个领域 → **+0.5**
- 覆盖 <3 个领域 → **+0**

### 5. 独立思考质量 (2 分)
- 含「技术可行性分析」 → **+0.5**
- 含「市场影响预测」 → **+0.5**
- 含「对阿轩的关联影响」 → **+0.5**
- 分析有具体洞见(非套话) → **+0.5**

## 📝 Test Case 模板

每个 test case 是「prompt 输入 + 期望输出特征」:

```yaml
- id: TC-001
  name: 今日正常速报
  date: 2026-06-05
  prompt: |
    你是AI行业资讯采集助手...
    [完整 prompt 内容]
  expected:
    min_news_count: 5
    max_news_count: 8
    must_have_sections: ["# 🔥 AI 速报", "## 🧠 独立思考"]
    required_keywords: ["来源:", "技术可行性"]
    forbidden_keywords: ["家人们", "绝绝子", "重磅"]
    min_domain_coverage: 4
  actual:
    output: <run output 粘贴在这里>
    score: <人工打分>
    notes: <具体反馈>
```

## 🚀 跑分方法 (3 选 1)

### 方法 A: 纯人工 review (推荐先用)
- 跑完一次,把输出 + rubric 给我
- 我(或你)按 5 维度逐项打分
- **耗时**: 5-10 分钟/次
- **适合**: prompt 大改后验证

### 方法 B: LLM-as-judge
- 写一个 eval 专用 prompt,输入「rubric + 输出」,让 LLM 评分
- **耗时**: 1-2 分钟/次
- **风险**: judge 模型自身不稳定(今天就抽风)
- **适合**: 模型稳定后大规模跑

### 方法 C: 规则自动评分
- 用 Python 脚本跑禁词检测/分隔符检查/新闻条数统计
- **耗时**: < 10 秒/次
- **局限**: 只能评客观维度(总分 6/10),主观维度(独立思考)仍需人工
- **适合**: 每次改 prompt 后快速 sanity check

## ⏰ 跑分时机

| 触发场景 | 跑分方法 | 谁执行 |
|----------|----------|--------|
| Prompt 大改前 | 跑 baseline 评分,记录 | 阿轩触发 |
| Prompt 大改后 | 同样 case 跑一遍,对比 | 阿轩触发 |
| Cron 失败 | 检查失败原因是否「格式/内容」 | 已有 cron-health-check 覆盖 |
| 周日 self-improving | 抽样最近 7 天速报,趋势分析 | 周日 cron 触发 |

## 🔧 怎么用 (实战流程)

1. **想改 prompt** → 先复制当前 prompt 到 test case
2. **跑 1 次 baseline** → 记录分数
3. **改 prompt** → 同样 case 再跑 → 对比分数
4. **分数下降** → 回滚
5. **分数上升** → 部署 + 记录变更

每次改完把分数 append 到「历史基线」表。
