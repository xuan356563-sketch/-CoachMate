# TrainFlow 本地体验登录设计

## 目标

当短信服务不可用时，让 iOS 模拟器和 Flutter Debug 构建仍可进入 TrainFlow，验证本地训练功能。

## 设计

- 登录页在 Debug 构建显示“进入本地体验（不含云端功能）”。
- 用户仍需勾选服务协议与隐私政策。
- 点击后由 `AuthController.enterLocalPreview()` 切换为本地体验身份，路由按既有认证状态进入首页。
- 本地体验不请求验证码、不写访问令牌、不绑定真实账号，也不绕过 Release 构建的认证。
- 本地体验身份收到云端会话失效通知时保持本地会话；AI、赛事图片识别等云端功能仍按无令牌状态返回原有错误。

## 安全边界

- 开关由 `kDebugMode` 提供，并在控制器内部再次校验，不能只依赖按钮是否显示。
- Release/Profile 构建不展示入口，也不能调用本地体验登录。
- 不修改 FastAPI 登录、短信验证码、协议版本或生产路由规则。

## 验收

- Debug 登录页可见本地体验入口，未同意协议时不能进入。
- 同意协议后点击入口会进入 `/dashboard`。
- 本地体验不产生 token、账号绑定或业务数据清理。
- 关闭本地体验开关时入口消失，控制器拒绝进入。
- 现有短信登录与未登录路由测试继续通过。
