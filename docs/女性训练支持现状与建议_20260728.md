# 智练 TrainMate 女性训练支持：现状盘点与建议

调研日期：2026-07-28
调研范围：`zhuque-flutter-main` 全仓（`lib` / `backend/app` / `test`，排除 `.venv`）

---

## 一、结论

**性别在项目里被采集了，但几乎没有被使用。** 全仓只有一处真实用途。

---

## 二、现状：唯一一处真实用途

`Gender` 枚举（`male` / `female` / `other` / `unknown`）定义在
`lib/data/models/user_profile.dart`，引导页有下拉框，`UserProfile` 有字段，
并通过 `lib/data/local/athlete_profile_projection.dart:26` 以 `biological_sex`
落进 SQLite。

真正读它的只有一个地方：

**`lib/services/training_metrics_engine.dart:172`** —— Banister TRIMP 的性别特异系数。

| | k1 | k2 |
|---|---|---|
| 男性 | 0.64 | 1.92 |
| 女性 | 0.86 | 1.67 |

这个用法本身是正确的，Banister TRIMP 公式确实区分性别常数。计算前还会校验
`biologicalSex` 有效、心率数据齐全且 `heartRateCoverage >= 0.6`，否则回退到
其他负荷估算方法。

## 三、现状：缺失的部分

### 3.1 计划生成完全不看性别

`lib/services/four_week_plan_generator.dart` 实际读取的画像字段只有 8 个：

```
profile.mainSports
profile.trainingGoal
profile.trainingExperienceLevel
profile.weeklyTrainingDays
profile.dailyAvailableMinutes
profile.equipmentAccessType
profile.id
```

没有 `gender`。每日调整引擎同样如此，读取频次最高的是 `mainSports`（14 次）、
`weeklyTrainingDays`（9 次）、`dailyAvailableMinutes`（9 次）。

### 3.2 后端处方接口曾经连接收都没接收

调研时在 `backend/app` 内 grep `gender|sex|female` 结果为空——请求契约里根本没有
这个字段。而 `backend/app/ai_skills/training-plan-builder/SKILL.md:30` 却写着：

> **身体状态** | 性别、年龄、身高、体重、体脂率（如有）、伤病史、健康限制 | 决定负荷上限和动作选择

这是文档中的**声明**，实际 API 并不传。属于文档与实现脱节，与 07-26 研究报告里
发现的 README 脱节是同一类问题。

> **本次已处理**：新增了 `biological_sex` 白名单字段与用户授权开关，
> 并把 SKILL.md 改成属实描述。详见 `改动说明.md` 第二节。

### 3.3 内容层零覆盖

在 `lib/data/seed/` 下检索以下关键词，结果全部为零：

```
女性 / 月经 / 经期 / 生理期 / 盆底 / 骨密度 / RED-S / 能量可用性 / 铁 / 孕期 / 产后 / 更年期
```

动作库（本次扩展后 184 个）、知识库、提醒模块均无女性专项内容。

## 四、建议

这几件事的**证据强度差别很大**，不应一视同仁。以下按证据强度排序。

### 4.1 优先做：证据较扎实

**RED-S / 低能量可用性筛查**
相对能量缺乏综合征是女性运动员三联征的核心概念。可对「高训练量 + 体重下降 +
持续疲劳」的组合做提示，引导用户就医评估。**注意：只做提示与转介，不做判断。**
这与项目已有的康复免责逻辑（`rehab_page.dart:219-232`）是同一套模式，可复用。

**骨骼健康**
负重与冲击类训练对骨密度的价值，对跑者尤其相关。动作库本次已补入箱跳、
落地缓冲跳、深度跳等冲击类动作，**内容上已经够，缺的是解释**——可在知识库里
补一条，说明为什么跑者不能只跑。

**盆底功能**
产后与高冲击训练人群的实际需求，目前完全空白。这块需要专业内容支持，
建议引用权威来源而不是自行撰写。

### 4.2 建议先别做：证据薄弱

**按月经周期做负荷周期化**（卵泡期加量、黄体期减量那一套）

这个概念在健身圈很流行，但近年的系统综述普遍指出：原始研究**样本量小、
周期分期方法不统一、研究质量偏低**，结论不足以支撑具体的训练处方。

如果确实要做，建议只做到「**记录 + 呈现关联**」：把周期标记叠加到已有的
ACWR / TRIMP 曲线上，让用户自己观察自身规律，**而不是让算法自动改计划**。
后者是在用弱证据做强干预。

### 4.3 无论做哪一项都要注意

**月经周期、体重变化趋势等属于健康信息**，不能当普通字段处理：

- 本地存储需要考虑加密；
- 阶段 4 的云同步要单独评估这类字段是否上传、如何脱敏；
- 参考本次性别开关的做法：**默认关闭、用户主动授权、未授权时连摘要都不能泄露**。

**产品定位边界**：本项目不做诊断。涉及闭经、骨折风险、产后康复等话题时，
应引导用户咨询医生或专业康复师，而不是由应用给出结论。
