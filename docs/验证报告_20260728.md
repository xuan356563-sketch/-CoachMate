### 1.2 部位推导规则

用 Python 复刻 `bodyRegionsForExercise()` 的完整逻辑，对全部 184 个动作跑了一遍：

- **每个动作都能推出至少一个部位**，无遗漏；
- 分布：胸 19 / 背 36 / 肩 36 / 手臂 33 / 核心 27 / 臀髋 67 / 大腿前 51 /
  大腿后 22 / 小腿足踝 25 / 全身 40 / 心肺 20；
- 逐条验证了测试文件里的具体断言，包括：
  - 胸椎旋转 → 归 `back`，不归 `chest`
  - 高脚杯深蹲 → 含 `quad` + `glute`，不含 `cardio`、不含 `shoulder`
  - 农夫走 → 不含 `chest`
  - Thruster、后撤式波比 → 含 `fullBody`
  - 轻松跑、节奏跑、A Skip、下坡控速跑 → 均含 `cardio`
  - 每个部位动作数 ≥ 5

**这一步发现并修正了一个真实缺陷**：最初按全部 `targetMuscles` 推导时，
「肩胛稳定肌」「握力」这类稳定肌把深蹲、硬拉一起塞进了肩和手臂的筛选结果，
肩虚高到 64 个。改为只取前 2 个主要肌群后降到 36 个，分布才合理。

### 1.3 后端契约行为

| 输入 | 预期 | 实测 |

## 二、未验证的部分

以下**必须**在你的 Mac 上执行：

```bash
flutter analyze
flutter test
cd backend && pytest tests/test_training_prescription.py
```

静态检查覆盖不到的风险，按可能性排序：

1. **类型推断与空安全**：括号平衡不代表类型正确。
2. **Riverpod / Widget 生命周期**：`ExerciseListPage` 从 `ConsumerWidget` 改成了
   `ConsumerStatefulWidget`，`setState` 与 `ref.watch` 的组合需要真实 widget 测试确认。
3. **未使用的导入或变量**：`flutter_lints` 会报，静态检查器不会。
4. **既有测试的连带影响**：本次改了 `widget_test.dart` 的动作数断言和 3 处
   Skill 版本断言，但可能还有别处依赖动作库规模或 Skill 版本的断言未被发现。
5. **`test/data/exercise_library_expansion_test.dart` 里有一条会直接读磁盘**
   校验图片文件是否存在——跑一次就能兜住配图问题。
