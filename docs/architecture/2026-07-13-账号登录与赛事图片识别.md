# TrainFlow 账号登录与赛事图片识别

## 实施范围

本切片在不修改训练模型、本地 races Schema 和 PostgreSQL 表结构的前提下，接通 Flutter 手机号登录与赛事图片识别。所有业务页面必须登录，服务协议和隐私政策页面可以免登录访问。

## 会话与本地数据

- Access Token 仅保存在进程内存。
- iPhone Refresh Token 由 `flutter_secure_storage` 写入 Keychain；Web 只保存在内存，刷新页面后重新登录。
- 受保护请求遇到 401 时串行刷新令牌并重试一次；刷新失败立即清除令牌并回到登录页。
- `trainflow.installation_id.v1` 标识当前安装实例，账号绑定记录在 `trainflow.account_binding.v1`。
- 首个登录账号直接绑定现有本地数据；同账号重新登录继续读取；不同账号必须进入确认页。
- 确认切换会清除 SharedPreferences 中的 TrainFlow 业务键，保留安装 ID 后绑定新账号；取消切换会撤销新会话并保留原数据。
- 退出账号只撤销会话，不删除训练数据和账号绑定。

## 协议与短信

- 内部测试协议版本为 `internal-test-2026-07-13.1`。
- 开发模式固定验证码为 `246810`，只能在 `APP_ENV=development` 使用。
- 生产环境必须替换正式协议版本、配置安全签名密钥并使用腾讯云短信。
- 验证码、完整手机号、刷新令牌和供应商密钥不会进入接口响应、业务日志或测试快照。

## 赛事图片识别

- Flutter 支持 iPhone 拍照、相册和 Web 文件选择。
- 后端只接受 JPEG、PNG、GIF 和 WebP，单图最大 10MB。
- 图片以 Base64 data URL 发送给 MiniMax-M3；模型原始响应必须通过 Pydantic 严格校验后才能返回 Flutter。
- 模型只能提取图片中明确可见的名称、类型、日期、目标和赛道信息，无法确认的字段保持空值并返回警告。
- 识别结果只存在于临时 Provider，不覆盖赛事文本。用户点击“填入并编辑”后才进入现有文本解析器，最后点击“导入比赛”写入本地 races。
- 图片不写入磁盘、PostgreSQL、SharedPreferences 或日志。

## 配置与回滚

- Flutter API 地址通过 `TRAINFLOW_API_BASE_URL` 注入；未配置时使用 `http://127.0.0.1:8000`，显式生产地址必须为 HTTPS。
- MiniMax、腾讯云和签名密钥只写入被忽略的 `backend/.env`。
- 回滚 Flutter 登录时可移除新增路由守卫和认证 Provider；原业务路由和本地数据 Schema 未改动。
- 回滚赛事识别时可移除图片 Provider 和后端 `/v1/races/image-recognition`，原文本赛事导入仍保持完整。
