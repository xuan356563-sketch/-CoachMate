# ADR-0007：跑姿视频关键点与分项评估工具链

日期：2026-09-11。状态：工程实现已交付；真实姿态识别与真人精度验收未通过，正式入口关闭。

## 用户流程与发行边界

拍摄指引 → 相册选择 → 视频检查 → 连续关键点 → 时序测量 → 分项解释与证据 → 手动保存 → 核心历史只读。

首版要求固定机位、单人侧面、全身清晰、平地或跑步机、5–20 秒常速视频。用户必须确认拍摄条件及未经变速。系统只能检查时间戳、人体数量、可见度及连续性等可检测问题，不宣称自动识别坡度、拍摄方式、跑步动作或所有变速视频。

使用已有 iOS 15.5 最低版本、Flutter／Riverpod、image_picker、AVFoundation 和 Apple Vision；未修改依赖声明、锁文件或数据库表结构。技术依据：[Apple 人体姿态请求](https://developer.apple.com/documentation/vision/vndetecthumanbodyposerequest)、[视频轨道读取](https://developer.apple.com/documentation/AVFoundation/AVAssetReaderTrackOutput)。

验收发行使用：

```bash
flutter run --dart-define=TRAINMATE_RUNNING_VIDEO_PREVIEW=true
```

该开关仍受 `!kReleaseMode` 限制，不能用编译参数开启 Release 入口。保持现有登录、会员和数据授权流程，不提供绕过认证的测试路由。非 iOS 平台可以读取报告，但不能执行设备端视频提取。

- 新分析路由：`/motion-check/running`，归属动作分析，默认关闭。
- 报告历史：`/history/running`，归属核心历史，动作分析停用后仍可读取。
- 新流程不调用旧照片 Mock 结果，不使用旧照片分数，不生成综合百分制评分，不自动调整计划。

## 技能及公共接口

`feature.motion_check` 的 `MotionCheckPlugin` 委托装配拥有三个同版本本地技能。注册表确认真实能力存在，卸载时释放视频网关。

|能力标识|实现|责任|
|---|---|---|
|`feature.motion_check.running_pose_extract`|`RunningVideoPoseGateway`|解码、进度、关键点、取消及临时证据画面|
|`feature.motion_check.running_metrics`|`RunningMetricsService`|独立可测性判断、角度与周期测量|
|`feature.motion_check.running_review`|`RunningFormAssessmentService`|中文分项报告、证据时间点与来源版本|

新增可选 `PluginDescriptor.workflows`／`PluginWorkflowRef`。马拉松、越野跑、HYROX 引用同一动作分析流程；越野跑限平整场地，HYROX 仅跑步部分。引用不改变运动策略、主次运动组合或计划生成的依赖。运动与功能详情页展示引用归属及验收状态。

数据接口为独立的 `RunningPoseFrame`、`RunningPoseSequence`、`RunningMeasurements`、`RunningMetric` 和 `RunningFormReport`。旧照片数据、`MotionPoseFrame`、`AiSkillRef` 和训练计划来源结构保持兼容。

## 提取与测量规则

原生 `RunningVideoPoseCoordinator` 使用独立方法通道和进度通道。每个任务使用 UUID，逐帧解码，采样不超过 30 帧／秒，单段最多 601 帧；不把整段视频像素加载进 Dart。计算图像最大边缩至 960，保留校正后的画面比例及原始展示时间戳。缩略图按需生成，不持久保存。

旋转及镜像通过视频轨道变换归一到左上原点；Dart 几何计算恢复宽高比例。缺失点不补零，未知类型或缺少置信度拒绝解析。多人、主体缺失和检测到的主体跳变不作为有效帧。主体丢失后不跨身份重建有效序列；此策略较保守，仍不能替代专业人物追踪或保证身份判断绝对准确。

- 先按膝部有效覆盖率选清晰侧，再比较躯干覆盖率，完全相同选左侧；整段不切换腿。
- 每个相关点置信度至少 0.6，各分项独立计算覆盖率和置信度；关键点置信度不等于动作质量。
- 超过 0.2 秒的采样间隙、缺失点、无效帧和关键点跳变切断周期。
- 膝角三点中值滤波后，以至少 10° 的下降及回升确认屈曲峰。周期只在同一连续区间内计算，0.25–2 秒之外的峰间距排除为抖动或暂停候选。
- 至少六个完整周期、80% 有效帧，才解释节奏变异系数；≤5% 为“本段较一致”，≤10% 为“存在波动”，其余为“波动明显”。这些是尚待真人校准的工程分级，不是临床或最佳跑姿阈值。
- 躯干输出角度中位数及四分位距；膝部输出最小／最大夹角及可测周期的幅度变化。两项均要求80%有效覆盖，不套用标准前倾角或关节角度。
- 静止、幅度不足、时间戳／尺寸异常和数据不足返回“无法评估”及原因。
- 不输出最佳步频、触地时间、步长、冲击力、足部着地方式、损伤风险或医学诊断。

## 保存、安全与清理

报告须手动保存，最多20份，达到上限后由用户选定删除，不自动淘汰。保存记录包含三个分项、采集条件确认、规则与检测器版本、插件来源、证据时间戳及最多60帧代表性关键点。证据最多占30帧，其余均匀覆盖全段。历史只展示结构化指标与骨架，明确原视频未保存。

本地键为 `trainflow.running_form_reports.v1`，格式版本1。SQLite继续写 `legacy_documents.storage_key`／`payload_json`；SharedPreferences增加白名单键。没有新表、云同步变更或网络上传调用。

`RunningFormReportRepository` 等待 `flush` 才返回保存成功；失败恢复先前文档，回滚也失败时保留错误并阻止继续写入。账号域操作的 `commit` 包住保存与删除，沿用既有提交锁和业务清理规则。历史不创建视频控制器、不补算报告、不写数据。

SQLite复用启动链路的数据库目录备份排除和文件保护；iOS SharedPreferences在首次写入报告前将应用 `Library/Preferences` 目录排除备份，因此同目录其他应用偏好也不参与备份。目录保护失败不进行报告写入。

原生任务仅清理自己的 UUID 目录。原视频来自相册选择器返回的应用文件，工具链只复制到自有缓存目录，不删除相册原件或未知来源文件。相册选择器自己的缓存仍由其插件与系统管理。自有缓存排除备份，视频文件采用完整文件保护；启动清理遗留目录，清理失败阻止新分析。

取消同步使任务失效，原生队列排空且文件清理完成才确认取消。重复取消可等待同一清理，失败保留任务身份以便重试。返回离开、转入历史、插件停用、账号切换、后台及销毁均取消任务；迟到结果不能覆盖新任务或写入其他账号。

## 真人验收与回滚

新增入口保持非正式发行状态。获取授权侧面跑步视频及反例后，在连接的 iPhone 上执行以下验收：

1. 每份有效视频人工标注至少六个周期、十个可见膝角度，并记录拍摄方向、真实播放速度和标注者；不将素材自动提交仓库。
2. 周期时长中位相对误差≤10%，膝角中位绝对误差≤10°。不通过时保持入口关闭，依据证据修正规则版本，不能改标注掩盖误差。
3. 静止、黑屏、多人／身份不连续不能得到有效节奏等级。翻转、降帧和遮挡输入后，指标应相应变化或降为不可测，不能复用固定输出。
4. 真机验证界面响应、取消停止处理、缓存清理、断网可运行，以及视频不产生上传请求；模拟器和纯计算测试不能替代这些结论。
5. 全部完成后另行审核发行开关；本次不提交、推送或发布。

回滚关闭新流程发行装配即可，保留新报告只读解析和旧照片入口；不清空报告、训练记录、计划或整库还原。
