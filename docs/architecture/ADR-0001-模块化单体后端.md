# ADR-0001：采用 FastAPI 模块化单体后端

状态：已接受

## 背景

TrainFlow 仍处于个人训练计划 MVP 阶段。账号、同步和 AI 需要共享同一份用户数据、审计记录和安全策略。

## 决策

采用单个 FastAPI 服务，内部按 `api`、`core`、`db` 和后续领域模块组织。PostgreSQL 承担事务数据，Redis 仅用于短生命周期协调能力。

## 后果

- 降低首发部署、监控和跨服务一致性的复杂度。
- 领域边界应保留在模块内，禁止继续向 Flutter 的巨型训练控制器复制服务端逻辑。
- 当 AI 或通知存在明确独立扩缩容需求时，再通过队列拆分工作进程。
