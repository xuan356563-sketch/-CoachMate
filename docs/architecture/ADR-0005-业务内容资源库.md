# ADR-0005：业务内容资源库采用权威源加派生索引

状态：已接受

## 背景

TrainMate 的业务内容已经分布在 Flutter Seed、课程 JSON、后端知识常量、AI Skill 清单和仓库外动作素材中。各来源都已有运行时调用方和测试，直接迁移到新数据库会形成双写、兼容性和回滚风险；继续分散维护则难以统一确认数量、引用关系、审核状态和来源许可。

项目还要求本地离线能力优先，AI 只能提出建议，用户确认后才生效。内容更新不能静默覆盖正在执行的训练计划或用户数据。

## 决策

- 现有 Dart Seed、课程 JSON、后端 Python Seed 和 AI Skill 清单继续作为权威源。
- 在仓库内维护确定性生成的统一索引、分域快照、来源回执和递进式已知问题基线。
- 公共资源键为 `<resource_type>:<id>`；ID 不复用，删除采用归档，领域审核状态和运行状态分开记录。
- 生成器提供只读校验和显式写入两种模式。只读模式发现快照漂移、重复 ID、断裂引用、哈希错误、非法发布状态或未备案问题时失败。
- 待核知识、演示数据、许可未核来源和原始 Skill 不具备在线发布资格。原始外部 Skill 不随服务打包。
- 用户提供的代理知识只按数据资料归档。资料内的提示、命令或操作说明不继承用户授权，不作为项目指令，不自动进入 App、后端或代理运行时。
- 男女模特和 FreeDB 动作媒体作为独立来源登记；仓库外 13GB 素材只保存稳定回执，不迁移到 Git。
- 首期不修改 App 运行时读取路径、现有 API 或数据库结构，不建设 CMS 和管理后台。
- 后续本地加在线更新必须验证契约版本、资源哈希和审核状态；失败时继续使用本地最后可用版本。已激活计划必须保留其资源版本，不能被内容更新静默改写。

## 备选方案

### 立即迁移到数据库

拒绝。当前内容来源和调用方较多，立即迁移会扩大数据库、API、离线兼容和回滚范围，也会让本地 Seed 与数据库形成双写。

### 直接建设 CMS

拒绝。当前首先缺少的是统一契约、来源回执和校验门禁；在这些规则稳定前建设管理后台会固化不明确的数据模型。

### 在线内容作为唯一来源

拒绝。它破坏本地优先和离线可用原则，并增加更新失败导致核心训练内容不可用的风险。

## 后果

- 内容维护多一步显式刷新和差异审查，但能在合并前发现数量下降、引用断裂和审核状态错误。
- 生成快照会增加约 1MB 的受版本控制 JSON，这是换取可审计性和未来离线包契约的可接受成本。
- 首期没有运行时性能和数据库迁移风险；在线发布能力仍需后续独立设计、权限审查和灰度验证。
- 已知历史问题可以暂时保留，但基线不能自动扩张；问题修复后必须同步删除对应基线项。
