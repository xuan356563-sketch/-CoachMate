# TrainFlow 大陆云端 Phase 0 基线

## 目标

为现有本地优先 Flutter MVP 建立可演进的服务端边界，不改变当前 SharedPreferences 数据格式、路由、训练规则或 AI Mock 行为。

## 已落实的边界

- 后端采用 FastAPI 模块化单体，PostgreSQL 为事实数据源，Redis 预留给验证码限流、异步任务和缓存。
- 开发环境使用 `backend/compose.yaml`，生产环境目标为腾讯云中国大陆区域的 CVM、RDS PostgreSQL 和 Redis。
- DeepSeek 只能由服务端调用；本阶段只保留服务端环境变量，不读取、不转发、不调用密钥。
- Flutter 仍然完全本地可用。本阶段不新增 Flutter 网络依赖，也不迁移任何 `trainflow.*.v1` 本地数据。
- 图片和 GIF 动图继续作为动作媒体策略，不加入视频能力。

## Phase 0 交付

- 健康检查：`GET /healthz`。
- 自动生成的 OpenAPI 契约：`GET /openapi.json`。
- Docker Compose、环境变量模板、SQLAlchemy 基类和 Alembic 迁移链路。
- `20260712_0001` 空基线迁移。它只记录数据库演进起点，避免在未实施账号与数据同意流程前创建健康数据表。
- 后端单元测试和静态检查配置。

## 后续切片顺序

1. 账号：手机号验证码、会话轮换、设备管理、用户同意记录。
2. 云同步：先支持资料、身体指标、训练日志、疼痛记录、计划调整和提醒设置；使用客户端 UUID、版本号、删除标记和增量游标。
3. DeepSeek：以结构化训练建议 API 接入，服务端裁剪上下文、校验 JSON 输出并保留本地规则降级。
4. 系统通知、账户导出与删除、监控、备份恢复演练。

## 明确排除项

本阶段不创建云资源，不申请腾讯云短信模板，不写入真实数据库，不启用用户登录，不调用 DeepSeek，不改变 Flutter UI，也不实现支付、会员、穿戴设备、OCR、文件选择或系统分享。
