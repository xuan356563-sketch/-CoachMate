# ADR-0006：运动插件技能绑定

日期：2026-09-11。状态：第一步已实现并完成相关自动验证。

## 目的与边界

运动插件需要回答三个可验证的问题：它负责哪项运动、使用什么训练技能、声明的技能是否确实可以执行。此前已有独立运动策略和服务端专项片段，本次将二者的归属显式登记到插件描述，并由注册表、生成入口和管理页消费。

本次的“本地技能”是已有 `SportPlanStrategy` 的能力声明，不是新增的提示词文件或另一套算法。“云端技能”复用已审核的 `training-plan-builder`。不接入 Harness 运行时，不复制或下载安装外部技能，不修改训练算法、数据库、API 字段、认证或授权。

## 契约与运行检查

`PluginSkillBinding` 保存所属插件、技能标识、名称、版本要求、执行位置、用途、输入、输出、不可用说明，以及本地能力或云端运动与片段键。列表不可修改。

1. 描述构造时检查归属、重复技能、本地能力声明及本地版本一致性。
2. 插件初始化结束后，注册表确认每项本地技能已注册真实能力。缺少实现时，沿用初始化失败清理流程，不公开未就绪能力。
3. 云端新生成入口读取当前主运动的插件声明，与既有能力协商结果匹配技能标识、兼容版本、运动覆盖及专项片段。失败时显示中文原因，不发起生成，不修改有效计划。
4. 云端实际版本与来源哈希继续由现有 `AiSkillRef`、能力接口和后端审核链路管理。本地绑定信息不进入网络请求摘要。

本地版本采用精确版本；云端采用兼容主版本 `1.x`，当前仓库主清单为 `1.3.0`。允许同主版本正式发行及构建元数据，拒绝不同主版本和预发布版本。客户端不把当前内容哈希写死为插件版本；内容更新仍需服务端审核、来源核验及现有确认流程。

服务端缺少已声明的运动或专项片段时，新云端生成会被阻断，包括缺少片段元数据的旧服务端。用户可使用既有本地规则入口；历史记录、已生效计划及其来源读取保持原有流程。

## 用户界面

“我的 → 运动与功能”在上述七项能力下提供“查看技能”。详情展示用途、执行位置、版本要求、输入输出、不可用说明及本机运行状态。

查看详情只读取描述和运行时，不联网、不启动业务控制器、不写插件设置。停用插件后详情更新为“所属插件已停用”；本地技能通过能力注册状态显示是否就绪；云端显示“待请求时校验”，不会仅凭声明宣称服务可用。AI 中心或训练计划功能停用时显示所需功能。

2026-09-11 最终结果：**396 项通过、2 项既有失败**；其中本次新增 7 项测试全部通过。静态分析无问题，差异空白检查通过。

两项失败均在本次修改前的源码快照副本上独立复现：

- `周期重排等待中来源失效会清忙，重新启用后可以重试`：测试夹具固定日期与当前真实日期不一致，剩余日程不足导致期望请求次数 1、实际 0。
- `核心历史读取旧计划版本、日志和三类报告且不写存储`：历史页面滚动查找在测试第 54 行报 `Bad state: No element`。已确认与本次修改无关，根因尚未修复。

未删除或降低这些断言。此次没有重跑全项目 Flutter 测试、后端测试或 iOS 模拟器/真机流程，也未验证真实模型和线上服务；上述通过数仅代表列明的相关自动测试。

本机证据：`/tmp/trainmate-skill-bindings-final-tests.log`、`/tmp/trainmate-skill-bindings-final-analyze.log`；修改前快照与两项失败复现日志位于 `/tmp/trainmate-skill-bindings-20260911-95p5cknk/`。临时日志不是长期发布制品。

## 后续边界

本次完成显式绑定与验证。云端仍按主运动选择片段；主次运动技能组合、独立专项复盘技能、新算法需另行设计与验收。共享跟练和周报展示不能据此解释为新增了独立 AI 技能。

回滚本次应用代码即可恢复此前装配与界面；本次没有新增持久化字段或改写计划、训练记录，不需要数据库回滚。保留工作区其他未提交改动，不使用整库或整仓快照覆盖。
