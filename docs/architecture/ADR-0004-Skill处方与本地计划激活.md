# ADR-0004：Skill 生成处方，本地编译并确认后激活

状态：已接受

## 背景

训练计划既需要利用开发者审核后的 AI Skill，又必须保证模型不能直接决定动作、负荷、安全门槛或覆盖用户当前计划。PAR-Q+ 等运动前筛查也不能被复制成应用内问卷或上传给模型。

## 决策

- 服务端只向模型提供白名单化的非健康训练上下文和审核后的 Skill 运行时，返回固定结构的训练处方。
- Flutter 端使用本地模板把处方编译为四周计划，并执行完整规则与安全审计；AI 不提供动作 ID、医学判断或证据引用。
- 筛查状态只保存于与账号、安装标识绑定的本机安全存储中，不保存题目、答案或许可文件，也不进入 AI 请求。
- 只有筛查有效、上下文未变化、审计无阻断项且用户明确确认时，才以新版本激活计划；旧版本保留并允许回退。
- Skill、模型、网络或存储失败都不得静默覆盖当前计划，本地规则计划始终可用。
- V1 只能发布一个可选择的主 Skill。外部辅助 Skill 只能先进入不可执行的来源目录，经逐项哈希锁定和安全审核后，改写为主 Skill 的受限运行时或专项片段；原始提示词不得直接进入模型。
- 来源包缺少许可或独立验证时，不随服务发布原文，只保留来源收据、审核状态和哈希。来源哈希用于溯源，不属于科学证据。
- ABC 循环渐进法作为 `training-plan-builder` 的力量专项片段发布，不新增第二个主 Skill。模型仍只输出既有处方枚举；AB、ABC、ABCD、ABC 循环和四周渐进由本地确定性编译器完成。
- 力量片段只在健身房或混合器械条件下启用动作级 ABC 编译；无器械或基础家用条件由本地规则安全降级。固定重量、力竭、心率、营养、伤病和康复内容不得进入运行时或激活计划。

## 后果

- Skill 更新会使草稿或当前计划标记为待更新，但不会自动替换正在执行的计划。
- 服务端 Artifact 的确认和本地激活是两个可重试步骤；服务端已确认而本地写入失败时，界面必须明确显示“已确认但尚未激活”。
- 康复、受监督训练、未成年人、筛查待跟进和当前伤病限制不进入 V1 Skill 计划激活范围。
- 新增运动专项片段必须保持既有处方契约兼容；没有运动代码和本地模板的项目只能登记，不能回退或伪装为综合健身。
- ABC 计划在确认前额外检查四周动作稳定、渐进序列和减量组数；动作漂移、固定重量或力竭指令均为激活阻断项。
