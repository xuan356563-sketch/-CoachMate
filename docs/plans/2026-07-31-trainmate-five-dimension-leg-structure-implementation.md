# TrainMate 五维训练与腿部四要素实施记录

> 日期：2026-07-31  
> 结构策略版本：`training-structure-v1`  
> 发布状态：代码已实现，功能开关默认关闭，待内部验收后逐步开启。

## 一、实施边界

本次是在现有“泡沫轴→动态拉伸→激活→主训练→冷身反馈”五步流程上叠加结构层，不改变旧计划和旧 SQLite 数据的读取行为。

- 五维：力量、稳定、神经募集、离心能力、呼吸。
- 腿部四要素：足踝地基、离心与落地、动态稳定、爆发输出。
- 恢复、康复和休息课不强行补齐高风险维度，只保留稳定与呼吸。
- AI 只返回待确认处方；五维和四要素由服务端或 Flutter 本地策略确定性回填，不增加模型输入 Token。

## 二、数据与兼容策略

1. 动作层新增可选 `ExerciseTrainingProfile`，未标注的旧动作返回空画像。
2. 课程动作关联新增可选 `tempo`、`executionIntent`、`breathingCue`；缺失时保持旧行为。
3. 训练日新增 `dimensionFocus` 与 `structurePolicyVersion`；主维度最多两个。
4. 训练反馈新增可选落地质量“稳/晃/疼”；旧记录无此字段时正常读取。
5. 未新增数据库表或迁移，不影响现有用户数据。

## 三、本地编排规则

| 周期 | 主维度 | 其他维度 |
| --- | --- | --- |
| W1 适应 | 稳定＋呼吸 | 力量、神经、离心低量触达 |
| W2 构建 | 力量＋离心 | 稳定、神经、呼吸触达 |
| W3 强化 | 力量＋神经 | 稳定、离心、呼吸触达 |
| W4 减量 | 稳定＋呼吸 | 先削减离心与神经，保留轻力量 |

腿部课固定执行“足踝激活→落地/爆发→主力量→单侧动态稳定→足踝力量收尾”。W4 移除落地与爆发增量。初学者将腾空动作降级为无腾空快速向心。

## 四、硬性安全门禁

- 爆发动作组间休息不少于 90 秒。
- 爆发动作必须位于主训练前部。
- 跳跃动作必须声明 `unlockedBy: exercise-drop-landing`。
- 初学者计划中不保留腾空动作。
- W2、W3 离心量较前一周增幅不超过 20%。
- 腿部课的足踝力量动作必须收尾，避免小腿提前疲劳损害落地质量。
- 落地反馈选“疼”时仅写入本地疼痛记录，不上传原因。

## 五、Token 约束

- Flutter 结构编排和安全审计全部本地执行，0 Token。
- V2 处方在原严格 Schema 生成完成后回填 `structure_profile`，不修改提示词和 `max_tokens`。
- 结构策略版本进入处方摘要和缓存键，规则升级时缓存自然失效。
- 模型不输出动作 ID、解锁关系或结构标签，避免伪造引用和额外输出 Token。
