## 1. 项目定位与不可变原则

TrainMate 是本地优先的个性化训练应用：Flutter 覆盖 iOS、Android 与 Web 客户端，FastAPI 后端提供账号、赛事图片识别、受控 AI 产物、云端数据能力和订阅校验。

1. 健康、疼痛、身体指标与恢复判断优先在本机处理；任何健康字段上云必须取得独立同意。
2. AI 只提出建议；画像、训练计划和周期重排须由用户确认后生效，并接受本地安全规则复核。
3. 不以 Mock、测试替身、模拟器构建或功能开关的存在替代真机、签名或线上验收。
4. 当前工作树包含大量未提交代码、素材与文档；候选版本必须绑定明确提交、依赖锁文件和素材清单。
5. 本轮不修改业务代码、数据库、API 契约、发布配置或既有 Web 能力；仅修订项目计划与启动记录。

## 2. 当前项目基线

## 3. V1.1 修订目标与范围

### 3.1 近期目标

近期唯一交付目标是形成可复现、可验收的 **iOS 内测候选版本**。在冻结候选版本后，测试者能够完成登录或受控本地体验、首次资料与隐私同意、训练计划确认、一次跟练与本地恢复，并访问动作库、赛事备战、身体数据和周报核心入口。

### 3.2 D0～D5 包含范围

- 完成批次 A/B/C 的 12 项文档修订，并建立变更记录。
- 召开 PO 决策会，归档六项决策、角色矩阵和外部依赖登记。
- 在 D5 通过定稿门禁后冻结 V1.1，定义 T+0，并启动 M0 的首日产物。

### 3.3 D0～D5 不包含范围

- 不执行 M1～M5 的工程改动、设备验收、预发布部署或分发。
- 不启用订阅、健康档案云同步、付费计划生成门禁或默认上传敏感健康字段。
- 不进行 Android 正式签名、商店提交、旧包迁移或 Web 发布。
- 不新增付费外部资源；本阶段外部资源预算为零。

## 8. V1.1 的关键执行条款

### 8.1 素材与失败用例

- 每个动作媒体必须被标注为“精确示范”“通用参考”或“媒体占位”。精确示范资源缺失时，默认显示明确占位或通用参考，禁止使用误导性文案。
- M0 使用失败用例决策网格记录测试 ID、观察结果、产品预期、归类、负责人、处置动作、验证命令和结论。
- 修复必须保留或加强回归断言；不得通过删除失败用例、降低断言或伪造资源使质量门禁通过。

### 8.2 AI 三项验收

1. 后端返回的 AI 产物必须是服务端校验后的结构化白名单结果，不保留原始提示词、音频、图片或 HealthKit 原始样本。
2. 画像、计划与周期重排默认处于“待确认”状态，用户未确认时不得写入正式业务结果。
3. 疼痛、健康和训练安全的本地规则优先于 AI；校验失败、超时、限流或上游异常时展示中文可行动提示并使用安全降级路径。

### 8.3 应用与数据回滚

- 异常时先关闭相关功能开关，再回退应用镜像或客户端版本。
- 回滚只切换应用版本，不执行 Alembic downgrade；数据库迁移必须向后兼容，恢复仅在新实例验证后进行，禁止直接覆盖原生产实例。
- 账号、健康、云同步和 AI 审计相关变更必须具备迁移、兼容、回滚和测试证据后才可进入数据库。

### 8.4 成本、合规、CR 与 Web 边界

- D0～D5 的外部服务预算为零：不得采购、充值或开启付费资源。任何费用、范围外文档修改或外部账号操作均须走 CR。
- 合规前置：数据流和最小化原则、健康字段独立同意、密钥仅受控注入、第三方服务条款/地域、删除与撤回路径、事故与回滚责任必须有可核验记录。
- CR 流程：提出人登记背景、范围、风险、成本、数据/API/安全影响、验证和回滚；客户端/后端/安全评审；PO 批准或拒绝；仅批准项可进入后续计划。D0～D5 的 12 项之外修改一律按 CR 处理。
- Web 保留现有代码与本地开发验证，不进入本轮发布、真机验收、TestFlight/Ad Hoc 分发、成本或上线承诺。
