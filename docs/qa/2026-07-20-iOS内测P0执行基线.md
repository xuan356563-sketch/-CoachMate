# TrainMate iOS 内测 P0 执行基线

## 目的

记录本轮修改前后的证据边界，避免把未提交工作树、模拟器画面或临时构建误当成可复建发布版本。

## 修改前基线

- 分支：`main`
- 起始提交：`3b541ff`
- 工作树在本轮开始前已有大量用户改动和未跟踪实现；本轮不清理、不重置、不自动提交。
- iOS Bundle ID：`com.example.zhuqueFlutterDemo`
- Android Application ID：`com.example.trainflow_ai`
- 仓库内没有已确认的正式 Bundle ID，因此本轮不擅自替换应用标识。
- 当前模拟器可安装并渲染 App，但本地 `127.0.0.1:8000` 没有 TrainMate 后端监听，登录页显示服务不可用。

## 本轮限定修改

- 身体数据删除增加明确确认和不可逆范围说明。
- SQLite 无法安全打开时提供重试、只读恢复说明和脱敏诊断复制。
- Release 启动必须显式提供 HTTPS API 地址，并拒绝 localhost。
- 增加上述行为的 Widget 和单元测试。

## 明确未处理

- 未修改 Bundle ID、签名团队、Provisioning Profile 或 App Store Connect 配置。
- 未清理 AppleDouble 文件或原工作区构建产物。
- 未启动、部署或修改后端服务。
- 未实施 P1/P2 项目。

## 验证要求

- `flutter analyze --no-pub`
- `flutter test --no-pub`
- 使用有效 HTTPS `TRAINFLOW_API_BASE_URL` 的 iOS Simulator Release 构建
- 获得正式 Bundle ID 后，另行执行 Keychain、SQLite 容器和覆盖安装迁移验证
